# Lido

A CDDL-to-DTO compiler in Rust: parses CDDL schemas and generates
encoding-independent DTOs plus a runtime library for C++, Java, and Rust.
**Current phase: 2 — the Rust runtime library.** Phases 0–1 are done: the
workspace, CI, and the conformance corpus (`conformance/`) exist; the compiler
does not.

## Documents

Documents of record — normative:

- `doc/specs.md` — requirements (EARS, ~250 `REQ-*` IDs)
- `doc/design.md` — architecture, workspace layout, wire format
- `doc/code-style.md` — style of **generated** code
- `doc/decisions.md` — append-only decision log; read this before
  re-deriving any decision

Process and sequencing — not normative:

- `doc/plan.md` — phases and slices, each with its own DoD
- `doc/development.md` — the loop, the gates, prompt shapes
- `doc/slices/*.md` — per-slice implementation plans, historical
- `doc/rust-style.md` — Lido's own Rust style (the self-review checklist)

## Non-negotiables

1. **The specs are read-only during implementation.** An implementation PR
   must not modify `specs.md`, `design.md`, or `code-style.md`. If one is
   wrong, stop and say so — that is a separate docs PR.
2. **The conformance corpus is ground truth.** Expected vectors under
   `conformance/` are never generated by Lido's own runtime and never edited
   to make Lido pass.
3. **Every test names the `REQ-*` ID it covers**, in the test name or a doc
   comment on it.
4. **Never bulk-accept snapshots or golden files.** Read each diff, accept
   individually, and explain the change in the PR body.

## Workflow

One slice = one branch = one PR. Plan first, into
`doc/slices/<id>-<slug>.md`, committed as the branch's first commit and not
edited afterwards; deviations go in the PR body, not into the plan.
